# 法条、案例、文献核查 Prompt

## 适用场景

当你担心论文中的法条、案例、裁判要旨、文献出处被 AI 写错或编造时使用。

## Prompt 模板

```text
你是一位法学论文事实核查助手。请只做核查规划和风险标记，不要编造任何不存在的信息。

【待核查内容】：粘贴法条、案例、脚注、参考文献或论文片段
【论文主题】：填写主题
【使用目的】：正文论证 / 脚注 / 文献综述 / 案例分析 / 投稿前检查
【目标法域】：中国大陆法 / 比较法 / 国际法 / 其他

请按以下结构输出：
1. 将待核查内容拆成“法条”“案例”“文献”“法律命题”“统计或政策信息”五类。
2. 对每一项给出风险等级：高 / 中 / 低。
3. 说明为什么有风险，例如条文可能修订、案号缺失、裁判要旨未核实、文献页码缺失。
4. 给出推荐核查来源，例如国家法律法规数据库、最高法官网、中国裁判文书网、北大法宝、CNKI、万方、HeinOnline、Westlaw。
5. 给出可复制的检索关键词。
6. 给出核查后应记录的字段：来源链接、访问日期、条文版本、案号、页码等。
7. 标出论文中必须改写的模糊表达，例如“司法实践普遍认为”“通说认为”。

硬性要求：
- 不要代替数据库核查后给出确定结论，除非我已经提供了原文证据。
- 不要补造案号、裁判日期、作者、期刊、页码。
- 对无法确认的信息，明确写“无法基于现有材料确认”。
```

## 需要替换的变量

- `【待核查内容】`
- `【论文主题】`
- `【使用目的】`
- `【目标法域】`

## 示例输入

```text
待核查内容：
《个人信息保护法》第24条要求平台不得进行大数据杀熟。最高法院在某平台算法推荐案中也确认了算法透明义务。
论文主题：自动化决策透明度义务
使用目的：正文论证
目标法域：中国大陆法
```

## 预期输出

AI 应指出“不得进行大数据杀熟”是否为条文原文需要核查，“某平台算法推荐案”缺少案名和案号，不能直接作为论据。

## 注意事项

- 核查 Prompt 不是数据库本身，它帮助你列出核查任务。
- 正式论文中每个关键法律判断都应能追溯来源。
